# 비밀 변수와 복구

Tessra의 비밀 변수는 사용자가 명시적으로 선택한 환경/Workspace 변수다. 이름이 token/password처럼 보인다는 이유로 기존 값을 자동 분류하거나 삭제하지 않는다. 요청의 `{{variable}}` 치환은 활성 환경만 사용한다. Workspace 변수는 편집·보호·백업할 수 있지만 요청의 전역 fallback으로 사용하지 않는다.

## 사용자 동작

- **Protect / 비밀 보호**: 기존 평문 변수의 현재 값을 보호한다.
- **Set value / 값 설정**: native 비밀번호 입력으로 비밀값을 명시적으로 설정/교체한다. 빈 값을 사용자가 입력한 경우와 키체인 항목이 없는 경우를 구분한다.
- **Reveal / 값 보기**: 현재 편집 범위에서 사용자가 요청한 값만 일시적으로 표시한다. Hide, 편집 범위/프로필 변경, 패널 종료 때 해제한다. 기본 Webview 메시지에는 실제 비밀값을 포함하지 않는다.
- **Delete secret variable / 비밀 변수 삭제**: 선택한 안정적 변수 ID와 현재의 정확한 secret 참조만 삭제한다. 같은 이름의 다른 변수/환경/프로필이나 과거 참조를 이름으로 검색해 삭제하지 않는다.

비밀값이 필요한 요청에서 값 미설정, 보호 진행 중, 키체인 사용 불가를 발견하면 실제 전송 전에 알려준다. 빈 문자열이나 원래 평문으로 대체해 전송하지 않는다. 사용하지 않는 변수 때문에 무관한 요청을 차단하지 않으며, 신뢰된 스크립트가 실행되는 경우에는 환경 값 전체를 읽을 수 있으므로 필요한 비밀값 확인 범위가 넓어진다.

## 변환과 중단 복구

1. 현재 JSON 원문과 안정적 ID를 읽고 진행 중 참조를 디스크에 저장한다. 이 단계의 원문은 중단 복구용으로 보존한다.
2. 그 참조의 키에 SecretStorage 값을 저장하고 다시 읽어 정확히 저장되었는지 확인한다.
3. 원래 snapshot과 현재 저장 내용을 비교해 동시 변경을 덮어쓰지 않는다. 일치하면 JSON을 비밀 참조로 바꾸고 현재 `value` 평문을 제거한다.

키체인/파일 쓰기 실패나 중단 시 보호 진행 중 상태로 남고 원문을 잃지 않는다. UI는 이를 마스킹하고 실행은 차단한다. **Retry protection / 보호 재시도**는 기존 진행 참조로 저장·검증을 다시 수행한다. **Cancel protection / 보호 취소**는 사용자가 선택한 정확한 진행 참조를 삭제하고 원래 평문 변수로 되돌린다. 실패를 무시하고 평문 저장으로 계속 진행하지 않는다.

값 교체는 새 참조에 저장·검증한 뒤 참조를 바꾼다. 실패하면 기존 참조가 유지되고 새 입력값을 JSON에 저장하지 않는다. 기존 참조를 암묵적으로 삭제하지 않으므로 사용자가 별도로 보관한 이전 참조/복원 경계가 남을 수 있다. 같은 변수의 변환·취소·교체·삭제는 직렬화하고 외부 동시 변경은 비교 후 거부한다.

이 기능은 현재 JSON의 논리적 평문 제거다. 이미 작성된 백업, export, history, `.corrupt-*` 사본이나 다른 파일을 검색/삭제하지 않고 디스크의 물리적 보안 삭제를 보장하지 않는다.

## 저장과 이동

확인된 값은 `ExtensionContext.secrets`의 VS Code SecretStorage에 저장한다. VS Code가 보관 방식을 관리하며 호스트에 따라 사용 가능 여부가 달라질 수 있다. 저장 키는 안정적인 프로필 UUID, 환경 ID 또는 Workspace 범위, 변수 UUID, 참조 UUID로 분리한다. 표시 이름 변경과 중복 이름이 다른 secret을 선택하게 만들지 않는다.

새 workspace backup과 Postman 환경 export는 비밀 참조/비민감 metadata만 포함한다. 보호 진행 중의 복구 평문도 export에서 제거한다. Import/restore는 같은 PC에서도 새 참조를 만들고 **Value needed / 값 입력 필요** 상태로 남겨, 가져온 이름/ID가 기존 키체인 항목에 자동 연결되지 않게 한다. 마스킹 문자열은 값으로 저장하지 않는다. 외부 Postman `type: secret`과 `.env`의 실제 평문은 기존 import 의미를 유지하며 자동으로 SecretStorage로 옮기지 않는다.

평문 변수, 직접 입력한 인증값/헤더/요청 본문 등은 별도 보호 대상이 아니다. 백업의 모든 필드가 비민감하다고 간주하지 않는다. Workspace backup은 현재 프로필 교체이며 merge가 아니고, 사전 백업과 history/tab-state 제외 계약을 유지한다.

## 실행·노출 경계

현재 허용된 프로필/세대와 시작 환경의 참조를 확장 호스트에서 필요한 시점에 해석한다. 프로필 전환/패널 종료는 실행을 취소하고 지연된 응답/Reveal을 새 화면에 전달하지 않는다. 요청 미리보기·코드 복사·resolved URL/headers·진단·스크립트 로그 같은 앱 생성 데이터는 알려진 실제 값과 URL/JSON/Base64 같은 일반 인코딩을 마스킹한다. History와 앱이 저장하는 요청 snapshot은 `{{variable}}` 참조를 보존한다.

실제 요청 바이트를 마스킹해서 보내지 않는다. 서버가 받은 값을 echo한 응답, 수신 WebSocket 메시지, 응답 저장/비교에 사용자가 선택한 데이터는 그대로 유지한다. 신뢰된 script는 실행 시 실제 환경 secret을 읽고 요청이나 로그를 만들 수 있다. 알려진 값의 로그는 기본 마스킹하지만 임의 조합·해시·부분 문자열·사용자 변환을 모두 검출한다는 보장은 없다. 공유하기 전에 응답/스크립트 출력/직접 작성한 요청을 확인해야 한다.

Imported script는 계속 명시적 신뢰 전까지 비활성화하며 JSON 입출력 경계를 유지한다. Node VM은 OS 보안 샌드박스가 아니다. [스크립트 실행 경계](script-security.md)를 함께 따른다.

## 검증

키체인 실패/검증 실패/변환 중단/취소 경합은 가짜 SecretStorage에서, 디스크/백업은 격리된 실제 StorageService 파일에서 synthetic 값으로 검증한다. 프로필 경쟁·이름 변경·중복 이름·정확한 삭제와 복원·missing import·metadata-only 메시지·mask 값 저장 거부를 포함한다. 실제 Webview/local fixture와 최종 통합 검증 결과는 [2026-10-05 검증 기록](ui-secrets-sse-validation-2026-10-05.md)을 따른다. 실제 토큰, 회사 proxy 자격 증명, 유료 API를 사용하지 않는다.
